# BORDER 總部內部構造參考資料

本文件供 world-trigger Three.js 專案與 Codex 參考。**非官方完整建築圖**；切勿把推測的樓層或尺寸描述成原作事實。

## 證據分級
- A：動畫／漫畫畫面直接呈現的空間或功能。
- B：根據畫面推論的空間關係，尚未有官方平面圖驗證。
- C：為遊戲與建模所做的原創合理假設。

## 已見空間
1. **C 級訓練大廳（A）**：動畫第 19 集畫面有中央大型編號狀態看板、挑空大廳、兩側多層走道與樓梯、編號訓練室門口。可觀察多層空間，但無法確認實際樓層數、門後房間尺寸與完整環形動線。
2. **資訊展示區（A）**：第 20 集畫面可見大型螢幕展示戰鬥地圖或名單資訊，後方有訓練室門與走道。不可據此認定顯示幕與第 19 集看板必然為同一位置。
3. **藍色網格模擬場景（A）**：第 17 集呈現巨大室內／城市樣式的網格場景與建築模型。這是模擬戰鬥／訓練場景的視覺表現；**不可把模擬城市當成總部實體樓層**。
4. **隊員活動、指揮、技術與訓練設施（A：功能存在）**：作品中存在相關功能；彼此確切樓層及通道未由本批截圖證實。
5. **地下機庫與出入通道（B：待官方資料核對）**：二手設定整理提及，需對照 BBF 原文再確定細節。

## 建模時的分離原則
- physicalHQ：真實總部大樓，含訓練大廳、門、走道、樓梯、隊伍區、指揮區。
- simulationArena：獨立載入的模擬戰鬥場景；以傳送／載入流程進入，**不佔用等比例的物理樓層體積**。
- underground：可先預留機庫／地下通道接口，位置標註為待核對。
- UI：編號看板與地圖顯示幕應獨立於建築網格，資料可動態更新。

## 原則
保留現有遊戲功能、操作與場景；先建立可進入、可離開、可測試碰撞的總部空間，再逐步細化。不得憑空宣稱總部有 40 層或指定官方樓層編號。參考圖片清單見 references.md，建模與動線見 layout.md。
