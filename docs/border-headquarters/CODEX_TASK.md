# Codex 任務：BORDER 總部室內建模

此儲存庫是 Three.js + Vite 的非官方三門市 3D 網頁遊戲。請先閱讀 `README.md`、`docs/city-plan.md`、`docs/game-roadmap.md`、`docs/border-headquarters/README.md`、`layout.md` 與 `references.md`。

目標：保留既有玩法、場景、鍵位、戰鬥邏輯、效能及 GitHub Pages 部署，逐步建立可進入的 BORDER 總部訓練大廳，使用參考截圖重建多層挑空、樓梯、欄杆、編號門與資訊看板。

規則：
1. 所有空間設計標記 A（畫面明示）、B（畫面推論）、C（建模假設）。
2. 不要把虛擬戰鬥地圖當成總部真實樓層。
3. 不要聲稱存在未核實的官方樓層表、尺寸或完整平面圖。
4. 先做灰盒白模與碰撞／出入動線，再加材質與細節。
5. 不要覆蓋原本的 `README.md` 或城市、戰鬥功能。
6. 參考圖片若尚未加入儲存庫，請先檢查 `assets/references/border-hq/`；缺圖時依文字建模，並明確說明視覺精度受限。
7. 完成後執行專案既有測試與 build，記錄新增路徑、模型尺寸及效能影響。

## 新增需求：小隊房間與科技感電動門
- 為各小隊規劃可擴充的獨立作戰室，包含隊伍識別、戰術螢幕、座位、裝備與門禁；實際位置為建模假設，勿標記為官方設定。
- BORDER 內部大部分門使用**電動雙扇橫向滑動門**（兩片門板左右分開），不是一般鉸鏈門。
- 實作可重用的 SlidingDoubleDoor 元件／工廠函式，支援感應與互動開門、開關動畫、延遲關閉、碰撞更新、防夾與門禁。
- 優先在訓練室、小隊作戰室、走廊出入口使用；保留少量符合用途的其他門型。

## 完整室內探索規劃
請先閱讀 `docs/border-headquarters/explorable-hq-design.md`。這份文件是玩家從城市步行進入總部、搭乘電梯或走樓梯、進入小隊房、訓練室與指揮中心的最新設計與驗收標準。優先分階段實作，不得將文件存在視為功能已完成。

## 日常生活與後勤設施
閱讀 `docs/border-headquarters/daily-life-and-facilities.md`，將大型食堂、販賣機、住宿區、小隊房間個性化、休息區、操作員工作區、狙擊訓練場、立體投影室與地下物流通道納入長期建築規劃。區分官方支持的設施與遊戲原創補充，先以模組化白模和低成本可互動設備實作。

## 七項追加設施（遊戲原創 C）
依 `docs/border-headquarters/daily-life-and-facilities.md` 最新章節，新增健身房、醫務室、自習室、裝備維修室、倉庫、貨梯、消防與避難設備的可探索場景。先建可通行白模與碰撞，再逐步加入家具和互動。避難防火門不必強制使用一般科技感滑動門；請勿聲稱這些空間是官方已證實的樓層配置。

## 最高優先級：實體碰撞與可探索頂樓
基地所有可見的牆、地板、樓梯、門、窗、家具、屋頂與護欄都要有相符碰撞；玩家步行、衝刺、跳躍、蚱蜢、高速移動與電梯搭乘不得穿模。頂樓必須可由實體樓梯抵達、可步行探索，具屋頂設備與防墜護欄。請完整遵守 `explorable-hq-design.md` 的碰撞驗收清單，先做碰撞可靠的白模，再增加細節；不得把未實作內容宣稱已完成。

## 互動設備與 F 鍵操作（最高優先級）
閱讀 `docs/border-headquarters/interactive-equipment-spec.md`。基地每個處室的主要設備都需有對應的可用互動，尤其椅子／沙發／長椅按 F 坐下，再按 F 安全站起。使用統一互動系統、視線距離與遮擋判定、互動提示和狀態機；互動時保持實體碰撞，避免站起穿模。先檢查原有鍵位，不能破壞現有遊戲控制。對尚未實作的設備不要顯示假互動。

## 平台範圍（目前優先）
本階段只考慮桌面電腦鍵盤與滑鼠操作，優先 Windows 瀏覽器。F 鍵互動、Esc 退出、滑鼠視角及現有戰鬥鍵位需完整支援。暫不開發手機／平板觸控 UI、虛擬搖桿或行動版適配；保留未來擴充可能，但不得為手機需求拖慢桌面版開發。
