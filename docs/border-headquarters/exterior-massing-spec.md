# BORDER 總部外觀量體：下寬上窄的微內收防禦建築

> 使用者提供的動畫截圖是本次外觀比例的主要視覺參考。這是參照截圖形狀進行的遊戲建模要求，實際尺寸和角度均為 C 級設計假設，不宣稱官方數據。目前本資料夾已有 9 張參考 JPG，見 [references.md](references.md)。
> 最新使用者要求已取代本提案的外擴基座：入口與街道等高、移除舊石質基座及坡道；四側可用建築區深 160 m。實作以 [implementation.md](implementation.md) 為準。

## 外型關鍵
- 將**現有基地外觀**修改為「底部較寬、上部略窄」的厚重梯形／微斜壁壘式建築，不是上下等寬的普通盒子，也不是顯著金字塔。
- 四面主外牆自基座往上**小角度向內收斂**；保持整體接近直立、穩重而非過度傾斜。
- 建議初版以頂部外輪廓相對底部**每側內縮約 3%–6% 的底面寬度**試作，或以相近視覺效果為準；屬遊戲調整參數，非官方測量值。
- 基座要有向外擴出的厚實裙樓／護牆，轉角設置加厚的斜面立柱／堡壘感突出量體。
- 上緣保留連續的女兒牆、略高的角部塔狀結構與少量屋頂機房；局部窗格、水平分層與金屬接縫提升巨大設施的比例感。
- 不要把參考截圖的青藍透明線框當成最終材質；正式模型用實體不透明牆面（白灰／灰藍／金屬），線框僅供外型核對。
- 建築四周外觀應協調，從街道不同角度都能看出輕微的下寬上窄效果。

## 與現有基地和室內的一致性
1. **優先修改現有基地模型，不要另外在旁邊蓋第二棟基地**；保留三門市地圖、入口位置與既有玩法。
2. 外牆採斜面幾何，碰撞必須匹配；不可只有外觀傾斜但仍用舊的垂直碰撞盒。
3. 每層樓板的外輪廓與對應高度的外牆截面一致，內部走廊與房間不得穿出外牆。
4. 門、窗、門框、裝飾線與外牆相接，不得出現懸空、縫隙或穿模。
5. 基座、樓板、樓梯、電梯、各處室及屋頂仍需有實體碰撞。
6. 頂樓仍然**可經由實體樓梯到達並自由行走**；樓頂面積因內收略小，屋頂設備與護欄須重新佈置，避免與牆面重疊。
7. 若現有基地比例和室內空間不匹配，優先保持可通行的樓梯、走廊和門寬，再微調收窄幅度。

## Three.js 幾何實作方向
- 將底部和頂部的四角輪廓參數化，例如 `baseWidth`, `baseDepth`, `height`, `taperRatio`，使用分段截面或自訂 BufferGeometry 建立實際斜面牆體。
- 每一層按高度線性插值計算外牆輪廓；分段建立牆板、角部護牆、基座及頂部平台。
- 牆體採有厚度的封閉幾何；配套複合碰撞體或與幾何一致的三角網格碰撞，不可單純用整棟巨大碰撞盒堵住內部。
- 可使用低成本模組化牆板與共用材質，避免過量 draw calls；以實際現有專案物理／碰撞實作為準，不盲目引入新物理引擎。
- 屋頂、外牆、入口與室內樓板須在同一世界座標中對齊。

## 驗收
- 從正面、側面、45 度視角檢視，明顯但輕微下寬上窄，厚重、結實，不像金字塔。
- 玩家不能穿越外牆、轉角、基座、屋頂護欄，也不會在外牆與樓板交接處掉落。
- 玩家可從城市進入總部，使用各樓層、樓梯、電梯及頂樓；所有室內互動與 F 鍵坐下功能不受影響。
- 測試高速移動／跳躍撞擊斜牆，不得穿模或被彈入牆內。
- 完成後提供修改前後的不同角度截圖與碰撞測試結果；執行 `npm test` 和 `npm run build`。
