# BORDER 總部互動設備與 F 鍵操作規格

> 這是使用者指定的遊戲原創互動設計（C），不是官方作品逐項證實的設施。所有可見的設備先確保實體碰撞，互動再逐步擴充。不得宣稱尚未實作的功能已完成。

## 統一互動操作
- **F**：在可互動物件前執行主要動作，例如坐下、使用、開啟、查看、拾取；坐著時按 F 站起，或顯示「F 站起」。
- **E**：可保留既有遊戲功能；先檢查現有鍵位再決定是否用 E 作次要操作，**不得覆蓋既有戰鬥按鍵**。
- **Esc**：關閉目前互動面板／取消操作，依原遊戲 Esc 行為整合。
- 鍵盤、滑鼠與觸控設備都要能操作；行動裝置顯示「互動」觸控按鈕。
- 視線／準星附近 2–2.5m 內，選取最近且可見的互動目標；遮擋時不可隔牆觸發。
- 準星對準時顯示名稱及提示，例如「椅子｜F 坐下」「電腦｜F 使用」；不在範圍時隱藏。
- 互動有距離、朝向、使用權限、冷卻、角色狀態與阻擋檢查；長動畫時不可重複觸發。
- 對話與選單採統一 UI；關閉時還原移動控制、滑鼠鎖定與焦點；離開互動不會留下卡死狀態。

## 坐下／站起（最高優先）
1. 椅子、沙發、長椅、餐椅、會議椅都可按 F 坐下。
2. 每個座位有 `seatAnchor`、`approachPoint`、`exitPoints`、`facing`、`occupiedBy`、`sitPose`。
3. 按 F 前檢查空位、距離與座位前通道；角色先移動／對齊至可達座位點，再播放坐下動畫或暫用坐姿替代；相機保持自然高度與視角。
4. 坐下後禁止一般位移、跳躍、攻擊和衝刺；可轉頭、看 UI、使用座位旁指定設備；顯示「F 站起」。
5. 按 F 站起，先確認可用的退出點沒有障礙，再將角色放回地面合法位置；不得穿桌、穿椅、卡牆、瞬移到樓下。
6. NPC 與玩家座位佔用互斥；站起／離開區域／場景卸載時釋放佔用狀態。
7. 角色模型與椅子皆有實體碰撞；坐下期間可調整角色碰撞形狀但不能取消所有碰撞。

## 技術架構建議（Three.js + Vite）
- 使用資料驅動 `InteractableRegistry`，欄位：`id`、`type`、`mesh`、`position`、`radius`、`label`、`actions`、`accessLevel`、`enabled`、`state`、`onInteract`。
- 使用 `InteractionSystem` 每幀檢查視線、距離、遮擋、權限與角色狀態；所有設備共用提示 UI，避免每間房複製判定程式。
- `PlayerInteractionState`：`FREE`、`APPROACHING`、`SEATED`、`USING_TERMINAL`、`LYING_DOWN`、`IN_ELEVATOR`、`DIALOGUE`；進出狀態都需可恢復。
- 可互動物件保留碰撞體，開門／拉抽屜／移動椅子時同步更新碰撞。
- 所有需要面板的設備共用 `InteractionPanel`；保留鍵盤焦點及退出操作。
- 先做「F 坐下／站起」「F 開關門」「F 使用電腦」「F 操作電梯」「F 販賣機」，再依房間增加功能。
- 未實作的設備可顯示「尚未開放」，但不要假裝已可使用；避免每件擺設都有誤導性的 F 提示。

## 必須通過的驗收
1. 餐廳、作戰室、訓練室、宿舍、醫務室、健身房、頂樓的座位皆可按 F 坐下，再按 F 安全站起。
2. 玩家隔牆、隔玻璃、隔關閉的門無法操作另一側設備。
3. 坐下時無法穿過桌子／牆壁；站起時不會卡進家具或掉落。
4. 連續按 F、快速移動、樓層切換、UI 關閉、多人／NPC 佔位均不會卡狀態。
5. 電梯、雙開門與互動設備同步維持正確碰撞。
6. 原有戰鬥、城市探索與按鍵仍正常，桌面與手機皆能互動。
7. 完成 `npm test`、`npm run build`，並進行實際走動與操作測試。
